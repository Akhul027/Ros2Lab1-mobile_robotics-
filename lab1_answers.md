# Lab 1 Answers

## Question 1

The `/turtlesim` node provides the main simulation interface for the turtle. Based on `ros2 node info /turtlesim`, the node contains subscribers, publishers, and service servers that handle turtle movement, pose updates, and simulation control.

## Question 2

The `/turtle1/pose` topic publishes turtle position information periodically because it is generated by the turtlesim update loop. Meanwhile, `/turtle1/cmd_vel` does not have a fixed publishing rate during keyboard teleoperation because messages are generated based on keyboard input events.

## Question 3

For a differential-drive robot, the useful fields in a `Twist` message are `linear.x` and `angular.z`. `linear.x` controls forward movement and `angular.z` controls rotation. The robot cannot move sideways, so `linear.y` cannot be used.

## Question 4

The turtlesim node does not need to identify or manage each subscriber directly. ROS 2 middleware handles communication between publishers and subscribers, so turtlesim continues publishing normally when subscribers join or leave.

## Question 5

An action provides feedback during execution and allows cancellation before completion. A command such as "navigate to the kitchen" should use an action because navigation is a long-running task that requires progress feedback and possible cancellation.

## Question 6

I used `colcon build --symlink-install` when building the `lab1_turtle` package. This links the installed Python package to the original source files, allowing changes in `circle_driver.py` to take effect without rebuilding. For an `ament_cmake` C++ package, the source code would need to be compiled again after modification.
